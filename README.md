# 编年卡片 · 项目说明

一部以"卡片"为基本单元的个人研究库：不做事件流水账，而是在选定的坐标系上做多维卡片，积累后横向对比，**寻找不同时空反复出现的相似结构**。

当前的研究系列（同一份数据，不同的透镜，详见下方"研究系列登记"）：

- **编年卡片**——年份 × 地点，政治/经济/社会/科技/日常生活/艺术六维；
- **交互设计**——年份 × 产品/范式；
- **梵高研究**——年份 × 画作/时期，单艺术家的纵向卡片。

## 卡片的字段约定（三层结构）

### 第一层：固定骨架（所有系列的卡片必备，永不改）

**坐标池（全系列统一）**：表单与 YAML 使用同一组坐标字段——`年份、地点、对象、范式、时期、别名`。每个系列只声明其中哪些**必填**（见登记表），其余可空；保存时空坐标字段不写入 YAML，老卡片缺字段完全兼容。

```yaml
---
年份: 1200                  # 可写区间，如 1195-1205；模糊时期可用"12世纪初"
地点: 杭州                  # 坐标池字段，非本系列必填项可留空（保存时不写入）
对象: 西湖图                # 坐标池字段
系列: [编年卡片]            # 所属研究系列，数组，可多属（跨系列卡片写多个值）
标签: [商业化城市, 官僚制]   # 横向检索的钩子，宁多勿滥
更新: 2026-09-19            # 最近编辑日期，录入卡片保存时自动写入；日期不进文件名（文件夹名是双链锚点，改名会断链）
---
```

`系列` 是数组的含义：一张 1200-杭州 的卡片可以同时属于"编年卡片"和"印刷史"两个研究——**研究方向是筛选条件，不是文件的物理归属**；文件夹只是给人导航用的，检索永远靠属性。

### 第二层：坐标轴与维度（各系列推荐组合不同，见登记表）

- **维度是"推荐问题清单"，不是围墙**：任何系列的卡片都可以添加维度池里的任何维度（录入卡片维度区有"+ 添加维度"入口）；跨系列写卡时优先用自选维度。
- **维度池**：下面登记表中出现过的所有维度构成全库维度池，自选维度**用词必须与池一致**（保证检索可聚合）；想发明新维度，先在池里登记再使用。
- 每维度写 2-5 句"当时的常态"即可，不求全面，求**具体**（有数据、有名物、有例证最好）。
- 老卡片缺某个维度是正常的，不要为了补齐而补齐。

### 第三层：扩展维度（按研究需要"长"出来）

新增维度（信仰、气候、物种等）＝ 新增一个 `## 标题` 小节。规则：

1. 先改本 README 登记一笔（见下方"研究系列登记"），再改模板和录入卡片；
2. 不回头补填老卡片，研究到哪补到哪；
3. 专题性、跨卡片的概念优先用**标签**而不是字段。

### 关系与来源

- 卡片之间的影响/关联用双链写在卡片末尾：`参见 [[1300-镰仓]]`——**跨系列也可以链**（如梵高卡片 → 编年卡片）；
- 每张卡片末尾必须有 `## 来源`，哪怕一句"《东京梦华录》卷三"。

## 研究系列登记（新增系列或维度在此登记，先登记再动手）

坐标池统一为 `年份/地点/对象/范式/时期/别名`，系列只声明**必填组合**；维度是各系列的推荐问题清单。

|------|--------|------|------|----------|

| 交互设计 | 年份、对象、范式 | 技术基础/交互隐喻/美学风格/用户群体/商业模式/争议与批评 | 交互卡片模板.md | 2026-09-19 |

**维度池（全库维度清单，自选维度从这里选词；新维度先登记再使用）：**
政治、经济、社会、科技、日常生活、艺术、技术基础、交互隐喻、美学风格、用户群体、商业模式、争议与批评、构图与笔触、色彩策略、题材与动机、心理与书信、技法实验、后世影响

新增一个研究系列的两步：① 本表登记必填坐标与推荐维度 → ② 打开录入卡片的「系列管理」新增并保存（自动写入 `模板/系列配置.md`，也可直接手工编辑该文件）。模板文件可选，主要给人看参照。

**系列注册表（`模板/系列配置.md`）** 是录入卡片工具读取的唯一系列来源：改系列名、改必填坐标、改推荐维度、增删系列都在这里完成（界面里点「系列管理」或直接改文件）。注意两点：

- 改系列名**不会追溯**已有卡片——旧卡片的 `系列` 字段保留旧名，仍可检索，必要时再批量替换；
- 未连接数据源时在「系列管理」里的修改只在本页内存生效，连接项目文件夹（或配置 GitHub）后保存才永久写入。

## 命名规则

- 卡片文件夹（按系列，见各系列登记行的坐标轴）：
  - 编年：`年份-地点`，如 `1200-杭州`、`1700-阿姆斯特丹`
  - 交互：`年份-对象`，如 `2007-iPhone`
  - 梵高：`年份-地点-对象`，如 `1888-阿尔勒-夜间咖啡馆`
- 图片文件：`年份-地点(-对象)-内容-作者.jpg`，如 `1200-杭州-西湖图-李嵩.jpg`
- 收集来的图先压缩（长边 ≤2000px）再放进卡片的 `图/`——用录入卡片拖图会自动压缩转 JPEG；手工放图时自行压缩

## 工作流

1. **随手记**：手机上想到什么扔 `_收件箱/`，格式随意；
2. **正式录入**：打开录入卡片（GitHub Pages 网址或库内本地 `录入卡片.html`，内容一致）→ 选系列 → 填表拖图 → 保存：
   - **GitHub 主库模式（推荐，任意设备可用，手机含）**：在录入卡片"GitHub 主库设置"里配置仓库与令牌（建议私有仓库 + 细粒度 PAT），生成的卡片和图片直接提交到仓库；电脑上用 GitHub Desktop 把仓库克隆到华为云文件夹，pull 获取新卡片，Obsidian 改动后 commit + push 回仓库；
   - **本地直写模式（未配置 GitHub 时）**：电脑版 Edge/Chrome 上选择一次本项目文件夹，直接写入；文件夹只需选一次——句柄记在本机浏览器（IndexedDB，两个工具共享，不进仓库），之后同一会话再开自动连接，重开浏览器点一下「继续使用」即可（浏览器安全模型禁止网页感知自身路径或凭路径开目录，这是纯前端的最省步骤）；
   - **兜底**：都不可用时点"复制文本"，粘贴到备忘录或 Obsidian（也可以手工复制模板填写）；
3. **对照发现**：卡片积累后，打开阅读卡片（库内双击本地文件或 GitHub Pages 网址，数据源与录入工具相同：本地文件夹只读连接或 GitHub 令牌）——标签点选聚合、全文检索、双链跳转与自动反向链接、勾选两张卡逐维对比；还有三个可视化视图：时间轴（年份分布）、关系图谱（双链网络，红色虚线节点即断链=下一步待写的卡片）、维度矩阵（每张卡写了哪些维度）；顶部"数据体检"列出断链/缺图/待补；在 Obsidian 里也可手工双链对照；
4. **定期备份**：GitHub 仓库本身即一份异地备份；华为云文件夹同步到云盘 + 移动硬盘各一份。

## 铁律

1. 数据永远是纯文本 Markdown + 常见格式图片，不绑定任何软件、平台、云服务（录入卡片只是一个"壳"，删了它数据毫发无损）；
2. 卡片是母本，网页/电子书等阅读形态都是投影，随时可重新生成；
3. 改数据约定（字段/结构）的顺序永远是：先改本 README → 再改模板 → 再改录入卡片 → 最后同步阅读卡片等投影；
4. 录入卡片只干"降低录入摩擦"一件事；阅读卡片只干"只读投影与对照"一件事（不写任何数据）；更复杂的分析/可视化留给将来的独立网页，各司其职；
5. 坚持比完整重要——从感兴趣的地方开始，让数据自己长成形状。
